Read and follow `.cursor/skills/babysit/SKILL.md`. That file is the procedure of record. This page lists only what changes in Claude Code. Do not copy the procedure here.

**Tokens:** the `scripts/babysit_*` scripts need a GitHub token in the environment (`GH_TOKEN`, or `PAWPET_CLAUDE_TOKEN` where the repo uses it). Do not rely on `GITHUB_TOKEN`.

## GitHub in Claude Code sessions

`gh pr …` subcommands call GraphQL, which this session cannot reach. They fail with 403. Use these instead (`<n>` is the PR number, `<sha>` the head SHA):

| Need | Command |
|------|---------|
| PR state, `mergeable`, draft | `gh api repos/AgathaTrack/AgathaTrack/pulls/<n>` |
| CI status | `gh api repos/AgathaTrack/AgathaTrack/commits/<sha>/check-runs` |
| Create PR | `gh api repos/AgathaTrack/AgathaTrack/pulls -f title=… -f head=… -f base=main -f body=…` (add `-F draft=true` for a draft) |
| Ready for review | `gh api -X POST repos/AgathaTrack/AgathaTrack/pulls/<n>/ccr/ready_for_review` |
| Review threads (unresolved) | `gh api repos/AgathaTrack/AgathaTrack/pulls/<n>/ccr/review_threads` |
| Reply to a review comment | `gh api -X POST repos/AgathaTrack/AgathaTrack/pulls/<n>/comments/<comment_id>/replies -f body=…` |
| Resolve a thread | `gh api -X POST repos/AgathaTrack/AgathaTrack/pulls/<n>/ccr/comments/<comment_id>/resolve` |
| Squash merge | `gh api -X PUT repos/AgathaTrack/AgathaTrack/pulls/<n>/merge -f merge_method=squash` |

A thread's `url` in the `babysit_pr_reviews.js` output ends in `#discussion_r<comment_id>`: that id is the one to reply on and resolve.

## Babysit scripts

`scripts/babysit_sync_base.sh` and `scripts/babysit_pr_reviews.js` run unchanged when `scripts/ccr-bin` is first on `PATH`. Its `gh` answers their two GraphQL calls (review threads, and `gh pr view --json baseRefName,headRefName`) from REST and the CCR review-thread route, and passes every other call to the real `gh`. Shell state does not persist between calls, so prefix each run:

```bash
PATH="$(git rev-parse --show-toplevel)/scripts/ccr-bin:$PATH" ./scripts/babysit_sync_base.sh --pr <n> --check
PATH="$(git rev-parse --show-toplevel)/scripts/ccr-bin:$PATH" node scripts/babysit_pr_reviews.js gate --pr <n>
PATH="$(git rev-parse --show-toplevel)/scripts/ccr-bin:$PATH" ./scripts/babysit_merge_preflight.sh --pr <n> --claim
```

The merge preflight (`babysit_merge_preflight.sh`, including `--claim` and `--release`) needs the same `PATH` prefix: its reads of `repo view`, `pr view` and `pr list` are answered by the wrapper. Without it, the preflight exits `3` on the GraphQL call.

Exit codes mean what the policy says, so the review gate is the policy's gate here too. The wrapper fails closed: an unknown query, a malformed thread, or a review comment no thread accounts for exits `1` with a `ccr-gh:` message. A script error is never a clean result: do not read it as "up to date" or "no threads", and never merge on it. Contract and tests: `scripts/lib/ccr_gh_shim_lib.js`, `scripts/ccr_gh_shim.test.js`.

Escalation, the merge rules and the policy links are unchanged. Related wrappers: `/babysit-plus`, `/babysit-uat`, `/pre-push-verify`, `/canonical-docs`.

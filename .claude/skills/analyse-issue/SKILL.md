# analyse-issue (Claude Code wrapper)

Read and follow `.cursor/skills/analyse-issue/SKILL.md`. That file is the procedure of record (engine-first steps, stop
conditions, Stage policy). This page lists only what changes in Claude Code. Do not copy the procedure here.

## Claude Code adaptations

| In the Cursor source | In Claude Code |
|----------------------|----------------|
| Rules: use `composer-2.5` for wake, poll and triage | Cursor-only model. Use the Claude model this session runs on. |
| Wake: `node scripts/issue_pipeline_wake.js --issue <n> --mission analyse --live` (runs `gh workflow run`) | Dispatch with the GitHub MCP `actions_run_trigger`: `method: run_workflow`, `workflow_id: issue-pipeline-v2.yml`, `ref: main`, `inputs: {issue_number: "<n>", mission: "analyse", live: "true"}`. Same inputs as the script. For a preview, use `live: "false"`. |
| Spec-agent and review-agent legs | No `.claude` wrapper exists. Read `.cursor/skills/spec-agent/SKILL.md` or `.cursor/skills/review-agent/SKILL.md` and follow it with Claude Code tools. |
| "If this run is the assignee, follow spec-agent" | The orchestrator never writes the spec or the review for the same issue (PIPE-V2-D-REV3-002: each run is independent). Follow a lane leg only when the engine has doorbelled this run for that leg. |
| Comments on the issue | End each one with `_Generated by [Claude Code](https://claude.ai/code)_`. |
| Waiting on another agent | Never `sleep`. Wait for the next engine wake or a subscription event. When a turn must end, park with `Parked on #<n> analyse; resuming on event.` |

Stop conditions, the Stage policy (the orchestrator writes To do at intake only) and the engine contract are unchanged.
